# Project Status Ledger
Last updated: 2026-10-21

This is the canonical record of current component status, durable validation outcomes, active issues, and validation debt. Behavior belongs in its owning concept document; reproducible checks belong in tracked test suites. Do not maintain standalone QA reports.

## Maintenance Rules
- A status applies only to the recorded scope and evidence. Source inspection or test existence alone is not a validation pass.
- Record the candidate revision, date, executed scenario, result, evidence link, and remaining limits. Update the existing slice row on rerun.
- Keep confirmed defects in Open Issues and insufficient coverage in Validation Debt.
- Link to the owning concept, tracked tests, or CI run. Keep transient artifacts in ignored scratch areas.

## Status Taxonomy

Component status is broader than a campaign result:

| Status | Meaning |
| --- | --- |
| VALIDATED | Confirmed through meaningful evidence for the stated scope. |
| PARTIAL | Confirmed for only part of the expected behavior or coverage. |
| BLOCKED | An external dependency or prerequisite prevents completion. |
| UNTESTED | No execution evidence is recorded for the scope. |
| NOT_IMPLEMENTED | The capability is absent. |
