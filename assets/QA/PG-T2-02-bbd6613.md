## Defect found and fixed

The first run of the new immediate-reload E2E exposed a state-loss race: a
reload immediately after template hydration could occur before the 150 ms
debounced localStorage write, leaving an empty editor after reload.

The scoped fix in [`workflowPersistence.ts`](../../app/client/src/workflow/hooks/workflowPersistence.ts)
flushes pending state synchronously on `beforeunload` and `pagehide`, while
retaining the existing debounced write for normal editing. The regression is
covered by [`nodes-config-models.spec.ts`](../../app/client/tests/e2e/nodes-config-models.spec.ts)
and passes with no adjacent workflow regression.
