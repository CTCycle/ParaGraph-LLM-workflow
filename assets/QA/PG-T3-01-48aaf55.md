## Scope

Close the remaining live browser gates left open by the `b0685c1` CI-backed
report: a checked-in Playwright suite drives the real Chromium UI against a live
uvicorn backend. The browser session imports the same five-node deterministic
workflow as a JSON bundle, uploads a nested TXT/Markdown directory through the
real folder picker, binds the staged folder into the Load Documents editor
field, exercises the Save As Folder picker path (File System Access dialog
stubbed, see honesty note), runs the workflow, reviews the JSON output artifact
in the editor, reloads to confirm graph persistence, and separately validates a
bounded failure path with a typed non-existent directory.

Out of scope (unchanged from `b0685c1`): PDF/DOCX/CSV/HTML format fidelity,
per-file and single-file upload lanes, upload security/limit behaviors, local
SQLite database node flows, vector/embedding stores, SQL adapters, and external
LLM/provider-dependent behavior.

## Harness findings fixed in this revision

1. **Windows relative path defect (product code).**
   `app/server/services/workflow/node_handlers/ingestion/documents.py` emitted
   `metadata.relative_path` via `str(path.relative_to(directory))`, producing
   backslash separators (`dataset\nested\notes.md`) that broke the
   backend integration contract's relative-path set assertion on Windows.
   Fixed to use `path.relative_to(directory).as_posix()`. This is the only
   emitter of the key and no frontend consumer of it exists.

2. **Stale node-name assertion in the live-backend contract spec (test only).**
   `real-backend-contract.spec.ts` asserted the literal node name
   `Secure HTTP Request`, but the catalog served by the repository resources
   root defines `Advanced HTTP Request` (the `data/nodes` manifest
   introduced by the resources relocation). The spec now reads the live
   catalog manifest name and asserts that text, so the assertion cannot go
   stale through manifest renames again.

3. **Live-Playwright CI launch never started the backend (CI harness only).**
   `.github/workflows/browser-e2e.yml` ran `(cd app/server && uv run python -m
   uvicorn server.app:app ...)`, which fails with
   `ModuleNotFoundError: No module named 'server'` because `server` is not
   importable from inside its own package directory. GitHub runs 37297404838,
   37449763501, 37606837696, 37765088097, and 37919026706 (2026-10-05 through
   2026-10-09 scheduled) all failed at the "Start backend" step for this
   reason, so the Playwright suites have not executed on CI since early
   October. The step now runs `PYTHONPATH=app uv run --project app/server
   python -m uvicorn server.app:app ...` from the repository root, matching
   `ci.yml`'s proven invocation pattern.

## Honesty notes

- The native **File System Access** directory-picker window cannot be
  automated by Playwright. The spec stubs `window.showDirectoryPicker` with a
  real `FileSystemDirectoryHandle` from the origin's OPFS
  (`navigator.storage.getDirectory()` +
  `getDirectoryHandle('pg-t3-01-save', {create: true})`), so the production
  handler still receives a genuine directory handle and streams chunks through
  the real `createWritable` path. What is stubbed is the OS dialog itself, not
  the product's picker wiring (both live in
  `app/client/src/pages/WorkflowPage.tsx`).
- The real directory **upload** picker path (dynamic `webkitdirectory` input,
  FileList with `webkitRelativePath`, `POST /nodes/uploads/directory`
  multipart staging) is exercised unstubbed, through
  `filechooser.setFiles(<directory>)`.
- The spec attaches detached file inputs to the DOM before each
  interception (`HTMLInputElement.prototype.click` wrapper) purely so
  Playwright observes the chooser; behavior of production code is unchanged.
- Screenshots and run JSON are sanitized: absolute staging paths inside
  `upload-run.json` are redacted with a `<RESOURCES>/` prefix. Screenshots show
  local absolute staged paths in the Load Documents field and the typed
  non-existent temp path in the failure dialog; they were reviewed before
  curation and contain no credentials, tokens, or provider data.
- Local `data/` side effects from the live run (staging folders, run artifact
  directories, and embedded execution rows) are developer-environment state;
  staging and artifact directories created by the runs were removed after
  evidence capture. The backend used the default `data` resources root because
  `resolve_resources_root` prefers `settings/.env` over the process
  environment.
