# PG-T0-03 Launcher Safety-Race Validation

- Date: 2026-09-23
- Status: `PARTIAL`
- Failure class: `ENV`
- Tested revision: `3de75204d7b7d790a617b17a122e2c72b0468d96`

## Scope

Cover the outstanding launcher safety cases for refusing to terminate the
launcher PID, process-exit and process-survival races, and detecting a listener
that reoccupies a configured port. Provider execution, the remaining frontend
build-input/failed-build matrix, warm-start timing, and a successful full
launcher start/stop cycle are outside this report's completed scope.

## Environment

- Windows `10.0.26200.0`; PowerShell `7.6.6`.
- Portable Python `3.14.2`, uv `0.11.12`, Node.js `22.12.0`.
- Backend and frontend dependencies were ready; the frontend build fingerprint
  was current.
- Configured launcher ports were `5002` and `8002` and were clear before and
  after the live attempt.

## Executed Scenarios

| Scenario | Method | Result |
| --- | --- | --- |
| Launcher PID is never terminated | Focused harness invokes the production confirmation function with the current launcher PID. | `PASS` — refusal was raised before any termination request. |
| Target exits during termination | Harness controls the process-existence check to switch from present to absent after the termination request, with a nonzero termination result. | `PASS` — the disappeared target counts as stopped. |
| Target survives failed termination | Harness keeps the target present and returns exit code 5. | `PASS` — the failure includes the taskkill exit code and PID. |
| Target survives a successful termination command | Harness keeps the target present and returns exit code 0. | `PASS` — the launcher still reports that the process is alive. |
| A replacement listener takes the port | Harness returns an original listener on the first scan and a different PID on the post-termination scan. | `PASS` — the replacement is reported and is not sent to termination. |
| Approved conflict termination through the official launcher | A task-owned PowerShell listener held configured UI port `8002`; option 1 identified its PID, and the confirmation was approved. | `PARTIAL` — Windows returned `Access is denied` from `taskkill.exe` (exit code 1). The launcher reported the surviving listener and aborted before starting the application. |

The live helper was then stopped directly by its verified task-owned PID. Both
configured ports were confirmed clear. No unrelated process was targeted.
