## Reproduced defects and fixes

1. The editor discarded `active_run` when polling returned `paused`, enabled a
   new run, and offered neither Resume nor Cancel. It now retains that ID,
   restores review controls on reload, rejects non-object JSON, and sends the
   reviewed object through the existing resume endpoint. New runs and session
   reset remain disabled while a run is tracked.
2. Live cancellation changed the run status but retained its pause checkpoint.
   The next read raised `ValueError: Persisted pause checkpoint is invalid` and
   the route returned HTTP 500. Cancellation now clears both checkpoint levels
   atomically and marks the paused step `skipped` with `execution_cancelled`.
   The real route regression proves readable cancelled state, ordered events,
   and HTTP 409 for repeated cancel and stale-token resume.
3. Monitoring failures discarded the browser's run ID. They now retain it for
   explicit Reconnect or reload. A definitive HTTP 404 releases tracking so a
   removed run cannot permanently lock the editor.

The recovery documentation was corrected: only queued/between-step runs recover
automatically. A step left `running` fails closed; it is not silently replayed.
