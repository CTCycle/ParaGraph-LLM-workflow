## Scope

Clean-checkout backend validation plus frontend install, lint, production
build, and unit tests. Browser E2E and provider services are out of scope.

## Planned scenarios

- Install the locked frontend dependencies in a clean runner.
- Run frontend lint, build, and unit tests without a developer-local

## Baseline execution

The exact inspected revision ran on GitHub Actions as follows:

| Job/step | Result | Observation |
| --- | --- | --- |
| `backend-validation` | `PASS` | Backend job completed successfully. |
| Frontend install | `PASS` | `npm ci --no-audit --no-fund` installed 329 packages. |
| Frontend lint | `PASS` | `npm run lint` completed with zero reported errors. |
| Frontend build | `FAIL` | Vite stopped before build output with `FASTAPI_HOST must be set in settings/.env.` |
| Frontend unit tests | `SKIPPED` | CI stops after the build failure. |

The failure is reproducible from the clean runner because `settings/.env` is
ignored and is not part of a checkout. `app/client/vite.config.ts` validates
all five build inputs (`FASTAPI_HOST`, `FASTAPI_PORT`, `UI_HOST`, `UI_PORT`,
and `VITE_API_BASE_URL`) before Vite can load its configuration. The local
developer environment had a populated `settings/.env`, so a local build alone
could not prove the clean-CI contract.

## Minimal remediation

The frontend CI job now supplies safe loopback values for all five required
inputs at the job environment boundary. The application’s strict
`requiredEnv()` behavior remains unchanged; no fallback was added to Vite and
no credential or external service is required.
